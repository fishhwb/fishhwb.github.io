Developer hub

Integration-ready by design.

FISH HWB is a static public website. It is deliberately kept separate from application credentials and backend services so future developer integrations can add their own callback and documentation paths without exposing secrets here.

Security rule: never put OAuth client secrets, access tokens, refresh tokens, signing keys or private API credentials in GitHub Pages files. This site should only contain public metadata, verification files, redirect/callback pages and documentation.

Current public integration surface

  • /auth/tiktok/ — static TikTok return/verification page.
  • /privacy-policy/ — public privacy policy route.
  • /terms-of-service/ — public terms route.
  • /assets/ — public branding and static assets only.
  • /.well-known/security.txt — security contact/handling information.

Adding a future developer app

  1. Create a dedicated /auth/<provider>/ route for any provider that requires a browser redirect.
  2. Keep provider verification files at the exact path/name the provider requires.
  3. Document only the scopes and data actually used by the application.
  4. Keep token exchange and secret-bearing API calls inside the desktop application or a properly secured backend — not this static site.
  5. Update privacy/terms when the data flows materially change.
