Privacy Policy

Last updated: September 9, 2026

Introduction

This policy covers the TikTok integration built into CubeZ, the local-first video tool Ded Zed publishes under the developer identity FISHHWB ("FISHHWB", "we", "our", or "us"). CubeZ runs on the operator's own computer, and your privacy is a core design principle of it.

Local-first design

CubeZ does not operate a cloud platform. It does not store user projects, prompts, generated content, configuration files, API credentials, or personal information anywhere but the operator's own device. Unless the operator deliberately uses an online integration, nothing leaves that device.

What CubeZ can publish, and to where

CubeZ can publish the operator's own videos and announcements to accounts the operator owns and has personally connected: TikTok, Facebook, Instagram, YouTube, Discord, Bluesky, Mastodon and Twitch.

What is sent. Only the video the operator has chosen to publish, and a caption built from that video's own title and description. Nothing else about the operator, and nothing at all about anyone else, is transmitted to these platforms.

What is received. Only what is needed to confirm which account a token belongs to — a username or display name — and whether a post succeeded. CubeZ does not read other people's content, does not collect audience or viewer data, and does not browse or scrape any platform.

TikTok specifically

CubeZ uses TikTok's Login Kit so the operator can authorise their own TikTok account, and TikTok's Content Posting API to upload the operator's own video to that account. It asks for two scopes when the operator signs in, and no others:

  • user.info.basic — used after sign-in, and by the credential check, to read the display name and open id so CubeZ can show which account is connected.
  • video.publish — used to upload the operator's own video file to that same account, through the Content Posting API's FILE_UPLOAD flow.

The app's TikTok registration also lists video.upload, which TikTok's Content Posting API includes by default and does not allow an app to remove; CubeZ does not use it, never posts drafts, and does not ask for it when the operator signs in. CubeZ reads no other person's content and makes no other TikTok API call. Once a video is posted to a platform, that platform's own privacy policy governs it.

How the TikTok connection is made. The operator starts sign-in from CubeZ, approves the request on TikTok's own consent screen, and TikTok returns them to /auth/tiktok/ on this site. That page is static: it displays the one-time authorisation code in the browser and sends it nowhere. The operator pastes the code back into CubeZ, which exchanges it for an access token and refresh token directly with TikTok and writes them to a configuration file on their own machine, readable only by their own user account. No server operated by us sees the code or the tokens, because there is no server behind this site.

Access tokens. Tokens are held by the operator, on the operator's own machine. They are never sold, shared, or sent anywhere other than the platform that issued them, and revoking a token in TikTok's own settings stops CubeZ using it immediately.

Analytics and cookies

CubeZ does not collect analytics regarding the operator's projects or usage. This site itself uses no cookies and no analytics; it is a static page with no server behind it.

Data retention

We do not retain the operator's personal information because nothing is stored on infrastructure we operate. Deleting local files or uninstalling CubeZ permanently removes locally stored data.

Your rights

Because CubeZ stores information locally, the operator maintains direct control over it and may view, modify, export or delete it at any time, without requesting permission from us.
